## Design limitation, not a bug (documented, not fixed)

- **Mixed test-authoring patterns across the suite (inline / fixture / custom-command / POM) are not technical debt in the usual sense** — see `docs/ARCHITECTURE.md`. Each pattern is the deliberate subject of its own course lesson. Item #13 above notes the real duplication this produces, but collapsing all 19 specs onto one pattern would remove the pedagogical point of the repo. Left as a judgment call for Phase 8, not a default "fix."
- **A third of the suite targets third-party demo sites this project doesn't control** (`seleniumbase.io`, `demos.telerik.com`, `demo.mobiscroll.com`, `demos.jquerymobile.com`, `the-internet.herokuapp.com`, `opensource-demo.orangehrmlive.com`, `reqres.in`) rather than the configured `baseUrl`. This is intentional per-lesson scope (each site demonstrates one UI pattern), not a mistake — but it is an inherent source of flakiness/availability risk outside this repo's control that no Phase can "fix," only document (Phase 5's `docs/BASELINE.md` should record it as a known limitation of the suite's determinism).

## Not treated as debt

- The repo being "just" Udemy course material with no application of its own is the nature of the repo, not a defect — `docs/ARCHITECTURE.md`'s "What this is" section documents this rather than treating it as a gap to fill.
- Zero runtime (`dependencies`) packages, 100% `devDependencies` — correct and expected for a pure test-tooling repo (confirmed by Phase 2's `npm audit --omit=dev` returning 0 vulnerabilities, as it should).
